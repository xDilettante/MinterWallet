# Мобильный интерфейс 0.8.5


## Выравнивание, копирование и регистрация Android 0.8.5

Заголовок «Адреса кошелька», значок и кнопка справки выровнены по вертикальному центру. Проверка использует
высоту TextLayout, а не растянутую область TextBlock: прежняя проверка границ не замечала смещение самого текста.
На мобильном справка открывает только Flyout, без одновременного настольного ToolTip.

На Android 13+ подтверждение копирования показывает система; дополнительная плашка приложения отключена.
На Android 8–12 и в предпросмотре остаётся собственное подтверждение. Источник платформенного поведения:
https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#duplicate-notifications.

На реальном телефоне отправка телеметрии получала HTTP 400 при включённой настройке. Публичный гейт сообщает
версию 0.6.3 и отвергает os=android с причиной «os: windows, linux, macos or other». Локальный код гейта уже знает
Android; установленный сервер ещё не обновлён. Клиент теперь использует совместимость только после этого точного
ответа 400: повторяет отклонённую регистрацию с os=other и тем же install id, версией, языком и сетью. На новом гейте
сразу сохраняется android. Прочие ошибки POST не повторяются; автоматической смены ID нет. На старом гейте телефон
учитывается в общих счётчиках, а в разрезе систем относится к other. Сервер и его конфигурация не изменялись.

После подтверждения пинга обновляется видимый счётчик, более ранний ответ статистики не заменяет новый.
При возвращении из фона отправляется пинг (с сохранением отказа от статистики, если настройка выключена).
В сведениях шапки доступен статус отправки этого кошелька; общие цифры не подменяются локальным прибавлением единицы.

Проверено на реальном телефоне после установки 0.8.5: публичный API гейта изменил online с 0 на 1, total с 3 на 4;
в списке версий появилась одна установка 0.8.5. Те же значения показаны в шапке, а в сведениях — подтверждение гейта.
Нажатие основного адреса показывает только серое системное «Скопировано», без зелёной плашки приложения;
заголовок и значки адресов визуально выровнены. Контрольные снимки хранятся только в игнорируемом artifacts.

## Отступы и управление кошельками 0.8.4

Пустые полосы выше/ниже навигации были повторным safe-area padding: начиная с Avalonia 11.1 корневой view учитывает
его автоматически, а MobileRoot дополнительно назначал SafeArea.Margin. В MobileRoot явно отключён
TopLevel.AutoSafeAreaPadding; системные панели/вырезы и клавиатура продолжают учитываться один раз вручную.
Источник контракта: https://docs.avaloniaui.net/docs/services/insets-manager. Ранее headless-проверки не выявляли
дублирование, поскольку у них нулевые системные отступы. Проверка теперь фиксирует, что владелец safe area один.

На устройстве обнаружена и вторая причина: ранние отступы сохранялись до установки RenderScaling (плотности экрана).
Теперь при изменении масштаба, размера и safe area читаются актуальные значения InsetsManager; обработчики снимаются
при отсоединении view. На телефоне 1080×2392 / 440 dpi проверены реальные границы: строка состояния — 105 пикселей,
жестовая область снизу — 49; лишние полосы устранены. Исходный код контракта масштаба:
https://github.com/AvaloniaUI/Avalonia/blob/12.1.2/src/Android/Avalonia.Android/Platform/AndroidInsetsManager.cs.

Кнопка раскрытия адресов сохраняет компактную иконку после переключения: прежняя текстовая привязка явно снимается,
иначе следующее изменение Expanded возвращало надпись, обрезавшуюся на телефоне. Добавлена регрессионная проверка.

Под строкой выбора кошелька постоянно видны сервер и три значения: онлайн / за 24 часа / всего. Данные берутся из
прежнего UsageAsync (без дополнительных пингов и идентификаторов), обновляются прежним минутным опросом;
при недоступности показывается «—». Нажатие открывает полный адрес источника и сведения о статистике. Онлайн —
активные установки за последние 10 минут, счётчики не означают число отдельных людей. Строка переносится при
больших значениях; имя источника ограничено своей колонкой.

Нажатие на отдельный полный адрес Minter/EVM копирует исходную строку, а не визуально сокращённый текст.
Показывается короткое подтверждение. Строки с несколькими адресами не угадываются; карточки-переключатели остаются
переключателями. Копирование своих адресов сохраняет PrepareReceive и защиту нестандартных путей; текст в полях
редактирования и секреты не перехватываются.

В выпадающем списке корневых кошельков есть «+», открывающий существующий мастер добавления, и корзина у выбранного
кошелька. Корзина открывает предупреждение об удалении фразы/ключа со всеми дочерними адресами. После отметки о
сохранённых данных восстановления требуется отдельное подтверждение с PIN/паролем/биометрией. Отмена ничего не удаляет.
Контекст хранилища/сессии проверяется после асинхронной аутентификации. На мобильном можно удалить последний кошелёк:
зашифрованное хранилище с прежней защитой остаётся пустым и показывает предложение добавить кошелёк. Настольный
двухшаговый сценарий сохраняет прежнее ограничение последнего кошелька.

Удаление на уровне Keystore теперь откатывает список адресов, секретов и имён в памяти, если запись файла не удалась.
Проверка воспроизвела прежнюю ошибку (после неудачной записи оставалось 2 адреса вместо 4) и проверяет сохранность ключа.
Удаление в мобильных сценариях выполняется только в созданном для теста временном хранилище. Проверены отмена,
аутентификация, удаление всей фразы с дочерними адресами, последний кошелёк, пустое состояние и добавление из списка.

## Компактные экраны 0.8.3

Шапка занимает один ряд (52 DIP без системных отступов) на всех основных страницах. Нажатие на название раздела
открывает выбор корневого кошелька и состояние соединения. Статические вступления убраны из форм в контекстную
подсказку «?», локальные пояснения — в значки возле соответствующих заголовков. Это явная разметка mobileIntro/
mobileHint: ошибки, комиссии, ограничения и поля не скрываются по длине текста или наличию класса prose.

MobileHelpButton использует штатную тему Button (StyleKeyOverride), открывает Flyout нажатием и ограничивает
размер содержимого доступным экраном. Android Back сначала закрывает подсказку/выбор кошелька. Тексты и динамическая
таблица стоимости токенов сохраняют DataContext; существующие «?» у уровней деривации также открываются нажатием.

Основной адрес показан полностью в одну строку через Viewbox с уменьшением только при нехватке ширины. Копирование
по-прежнему берёт исходный полный адрес. Сумма и монета перевода стоят рядом; для основной формы проверяется видимость
кнопки продолжения без прокрутки на 320×640. Поля выпуска токена сгруппированы попарно; развёрнутые правила с ценами
доступны отдельно. В мосте убраны повторные подписи маршрута; комиссия 1 % + газ остаётся на форме. Срок вывода стейка
также остаётся видимым. Сложные формы, длинные списки и экранная клавиатура продолжают поддерживать прокрутку.

Иконки wallet, coins, building-bridge из Tabler Icons используются как геометрия существующего Icon без нового пакета
или шрифта. MIT-лицензия включена в Assets/Licenses/Tabler.txt (источник: https://github.com/tabler/tabler-icons).

Дополнительные проверки: высота шапки, полный адрес без переноса/выхода за экран, основной перевод без прокрутки,
реальный pointer-down/up по «?», закрытие через Back и сохранение динамических данных в подсказке правил токена.

## Обзор и навигация 0.8.2

Изображения в переданном обсуждении ChatGPT появляются отдельно от текста. За основу взяты общие приёмы
тёмного примера с карточкой баланса и walletX: компактная шапка, баланс выбранного адреса, быстрые действия,
вертикальный список активов. Палитра, значки и понятия Minter Wallet сохранены.

MobileOverviewView — отдельная мобильная разметка над прежним MainViewModel. Вместо перестановки десктопных
элементов по отступам и типам удалён прежний AdaptOverviewPage. Получение/QR/запрос суммы/погашение чека и защита
нестандартного пути вынесены в общие ReceivePanel и DerivationProtection; мобильная и настольная версии используют
одни и те же привязки и проверки разрешения получения.

- Карусель деривации остаётся над выбранным адресом, сворачивается; параметры и точный путь остаются скрытыми
  до открытия редактора. На карточках сохраняются адрес, баланс и полный цветной путь.
- Основной адрес показывается полностью; рядом с названием — переименование и копирование с текстовым результатом.
  Цветной путь виден под адресом. Под ними — баланс текущего адреса, а не сумма всех дочерних адресов.
- Четыре действия: получить, отправить, обмен, мост. Стейкинг — отдельная нижняя вкладка и ссылка «Делегировать».
- Монеты — вертикальные строки: значок, тикер и количество слева, USD/RUB справа; при отсутствии фиатной оценки
  сохраняется оценка в базовой монете. Составная оценка не дублирует уже показанную валюту.
- Общая сумма адресов свёрнута в «Итог по адресам». Делегации, замороженные средства и последние операции доступны
  ниже списка монет. Меню разделов — сетка из двух колонок, ограниченная высотой экрана и с прокруткой.
- Шапка обзора компактнее; статичное обновление и обновление жестом сохранены. Другие разделы показывают своё
  название; на экране истории сохраняются CSV и отдельное обновление истории.

Дополнительные MobileChecks проверяют полное копирование адреса с обратной связью, прямые входы в мост/стейкинг,
четыре действия нужного размера, видимость начала списка монет над нижней панелью и отсутствие повторной оценки.
Аппаратная проверка биометрии описана в MOBILE_SECURITY.md.

## Предыдущая переработка экранов 0.8.1

## Выбор PIN при создании

Причина: Avalonia может создать MobileRoot во время Application.OnCreate, до MainActivity.OnCreate.
Службы телефона ещё не опубликованы, а прежний код запоминал отсутствие PIN один раз. Тесты подставляли
FakeMobilePlatform заранее и не воспроизводили этот порядок. MobileHost теперь сообщает о смене платформы,
WalletCredentials обновляет доступность PIN, а уже открытый CredentialChoice уведомляет привязки.
Слабая ссылка не удерживает отменённый мастер создания вместе с его фразой.

Проверка воспроизводит позднее подключение Android-служб, находит именно видимый переключатель, выбирает PIN
через контрол и создаёт тестовое хранилище шестью цифрами. Обычный пароль и существующие PIN-хранилища сохранены.

| Подтверждения | Сохраняется системная биометрия с запасным способом; увеличены размеры элементов |

Используется прежняя палитра, шрифты и значки кошелька. Основные поля — 48 DIP, действия — не менее 44 DIP.
Новые мобильные мастера используют существующие ViewModel; криптография и транзакционные алгоритмы не менялись.
Общие страницы размечены семантическими классами phoneFields/phoneStack/phoneRoute для мобильной компоновки;
настольная разметка сохраняет свои колонки.

Клавиатура учитывается по пересечению с клиентской областью. При уже уменьшенном Android окне высота клавиатуры
не вычитается второй раз; сфокусированное поле прокручивается в видимую область. Геометрия соответствует
[координатам InputPane относительно TopLevel](https://docs.avaloniaui.net/docs/services/input-pane).

## Проверки

MobileChecks: 40 снимков на каждом прогоне, русский/английский, светлая/тёмная палитры, создание с поздними
службами Android, PIN/пароль/биометрический сценарий, размеры всплывающего поиска монет, видимость нижнего действия,
отсутствие горизонтального переполнения, полный основной адрес без TextTrimming и геометрия клавиатуры.
Фикстуры показывают ненулевые балансы, монеты, стейки, замороженные средства и транзакцию, а не только пустой экран.

```powershell
dotnet run --project tests/MinterWallet.MobileChecks -c Release -- --size 320x640
dotnet run --project tests/MinterWallet.MobileChecks -c Release -- --size 360x800
dotnet run --project tests/MinterWallet.MobileChecks -c Release -- --size 412x915
dotnet run --project tests/MinterWallet.MobileChecks -c Release -- --size 360x800 --theme light
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check.ps1 -Wallet
```

Снимки: artifacts/mobile-checks*, раздельные каталоги для размера и светлой темы. Это проверки Avalonia.Headless:
системный сенсор биометрии они не эмулируют. APK собирается tools/build-android.ps1, подпись и совместимость
обновления описаны в MOBILE_SECURITY.md. Обновление выполняется поверх приложения, без его удаления или очистки данных.
