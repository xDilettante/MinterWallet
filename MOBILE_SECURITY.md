# Android: вход и подтверждения (0.8.2)

При создании или восстановлении кошелька пользователь выбирает PIN из 6–12 цифр либо пароль от 8 символов.
У существующего кошелька сохраняется прежний пароль. Сменить способ защиты можно в «Настройки → Безопасность»,
подтвердив текущий PIN/пароль. Новый способ записывается атомарно вместе с перешифрованными ключами в keystore.json;
при ошибке сохранения остаётся прежний способ. Без аппаратной службы Android вариант PIN не предлагается.

После успешного создания или первого входа приложение предлагает включить биометрию. До согласия секрет для неё
не сохраняется. «Не сейчас» запоминается; включить/выключить биометрию можно в настройках. После смены PIN/пароля
старый биометрический секрет удаляется, включение предлагается заново. При восстановлении другого кошелька
согласие сбрасывается. Экспериментальный biometric.dat и его незащищённый аутентификацией ключ удаляются при запуске;
они не используются для входа. Ошибка службы AndroidKeyStore при очистке не блокирует вход по паролю, очистка
повторяется при следующем запуске и перед включением новой биометрии.

При включённой биометрии вход и подтверждения сами запускают системный диалог. Повторная кнопка нужна только
для повтора. Отмена/недоступность/ошибка открывает PIN или пароль. Проверяется секрет именно текущего кошелька;
поздний ответ отменённого диалога не действует на следующий запрос. Уход приложения в фон отменяет запрос.
Неправильно введённый пароль/PIN не записывается в биометрический кэш.

## Криптография и ограничения

- Пароль использует прежние Argon2id + AES-256-GCM. Десктопные кошельки продолжают работать как раньше.
- PIN преобразуется HMAC-SHA256 с неэкспортируемым ключом AndroidKeyStore, затем поступает в тот же Argon2id.
  Сам PIN и HMAC-ключ не записываются в файлы кошелька. Копии keystore.json недостаточно для автономного перебора
  PIN без ключа исходной установки. PIN-кошелёк привязан к телефону/установке: на другом устройстве нужно
  восстановление по фразе/приватному ключу, а не перенос одного keystore.json.
- Биометрический секрет зашифрован отдельным AES-256-GCM ключом AndroidKeyStore с
  setUserAuthenticationRequired(true), а шифрование и расшифровка выполняются через BiometricPrompt.CryptoObject.
  Требуется новая сильная биометрическая аутентификация для каждой операции. При смене набора биометрии ключ
  инвалидируется; пароль/PIN остаётся запасным способом. Наличие аппаратного TEE/StrongBox зависит от телефона;
  приложение не заявляет их наличие только на основании AndroidKeyStore.
- После пяти неверных попыток PIN/пароля действует задержка 30 секунд, растущая до 5 минут. Счётчик сохраняется
  между перезапусками и общий для входа и подтверждений. Это защита приложения от подбора через интерфейс;
  она не защищает от контроля над процессом/root или модификации приватных файлов и часов ОС.
- Строки секрета в управляемой памяти не имеют гарантированного обнуления. Временные массивы PIN/расшифрованного
  секрета Android обнуляются после использования. Фраза/ключ не отправляются в сеть.

Документация: [Android: биометрия и CryptoObject](https://developer.android.com/identity/sign-in/biometric-auth),
[ключи с обязательной аутентификацией](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setUserAuthenticationRequired(boolean)).

## Обновление жестом

На мобильной верхней панели остаётся статичная кнопка обновления и индикатор соединения. Таймер/вращение убраны.
Обзор обёрнут штатным RefreshContainer: потянуть вниз в начале прокрутки — обновить, индикатор появляется только
при жесте; deferral завершается после обновления, включая ошибку. Фоновое автообновление не включает эту анимацию.

## Подпись и обновление старых APK

Прежний release-ключ был опубликован в Git и считается скомпрометированным. Он исключён из текущего среза/экспорта;
удаление файла из HEAD не удаляет его из истории. Новые релизы этим ключом не подписываются.

`tools/build-android.ps1` создаёт/использует приватный ключ в `%LOCALAPPDATA%\MinterWallet\Signing\release.keystore`,
пароль — в `release.signing.xml` (DPAPI текущего пользователя Windows). Доступ к каталогу ограничен текущим
пользователем и SYSTEM. Пароли передаются инструментам через environment, не в аргументах или логах. Ключ нельзя
терять: резервная копия ключа и доступного пароля необходима для последующих обновлений. DPAPI-файл сам по себе
не является переносимой резервной копией пароля. Возможна внешняя конфигурация четырьмя переменными
MINTERWALLET_ANDROID_KEYSTORE, MINTERWALLET_ANDROID_KEY_ALIAS, MINTERWALLET_ANDROID_KEY_PASSWORD,
MINTERWALLET_ANDROID_STORE_PASSWORD. Release без приватной конфигурации завершается ошибкой.

`artifacts/wallet-android/MinterWallet.apk` — единый APK для Android 9+ (arm64), новой установки и обновления.
При наличии release.lineage рядом с приватным ключом либо переменной MINTERWALLET_ANDROID_SIGNING_LINEAGE
скрипт включает proof-of-rotation в этот же файл; отдельного upgrade APK нет. Сертификат новый, подпись v3,
ротация действует начиная с API 28; v1/v2/v4 отключены. Цепочка была сформирована штатным apksigner rotate
с запретом rollback. Старый приватный ключ для выпусков не нужен. Android 8 больше не поддерживается.
`-Install` устанавливает этот же файл через adb install -r; при ошибке не удаляет рабочий кошелёк.

GitHub release требует секреты ANDROID_RELEASE_KEYSTORE_BASE64, ANDROID_RELEASE_KEY_ALIAS,
ANDROID_RELEASE_KEY_PASSWORD, ANDROID_RELEASE_STORE_PASSWORD и ANDROID_RELEASE_SIGNING_LINEAGE_BASE64.
Они настроены в закрытом хранилище GitHub Actions; ключ/пароли не включаются в код, артефакты или логи.

В уже опубликованном 0.8.5 состав загрузок упрощён без изменения тега: проверенный CI APK с ротацией теперь
распространяется под общим именем android-arm64.apk; отдельный upgrade APK убран, SHA256SUMS обновлён.
Следующие сборки также задают minSdkVersion=28 в манифесте (ранее APK с v3-ротацией имел minSdkVersion=26,
но сама подпись требовала Android 9). Версия приложения не повышалась из-за изменения упаковки.

Источники: https://developer.android.com/tools/apksigner,
https://source.android.com/docs/security/features/apksigning/v3.

## Проверки

`tools/check.ps1 -Wallet`: протокол, хранилище/API, десктопная деривация/телеметрия и мобильный UI.
MobileChecks проверяет согласие/отказ, PIN-импорт, перезапуск, задержку попыток, переход PIN→пароль,
автоматический биометрический запрос, запасной способ, опечатку без порчи секрета и поздний отменённый ответ.
Системная биометрия в этих проверках заменена FakeMobilePlatform — они не доказывают работу сенсора на телефоне.

`tools/test-android-biometric.ps1` собирает и открывает отдельное приложение `network.minter.wallet.biometriccheck`.
Оно компилирует тот же AndroidCredentials.cs и WalletPaths.cs, что и кошелёк, но использует только публичную тестовую
строку и собственную песочницу Android. «1. Включить» и «2. Прочитать» требуют настоящего отпечатка;
`-ReadResults` читает только коды результатов теста. Рабочий кошелёк не открывается и не сбрасывается.

На Android API 36 воспроизведён сбой 0.8.1: успешный отпечаток → IllegalBlockSizeException/KeyStoreException при
шифровании. Причина — UpdateAAD вызывался до per-operation авторизации; Android сохранял ошибку неавторизованной
криптооперации, и последующий успешный отпечаток её не исправлял. UpdateAAD перенесён после CryptoObject-авторизации
перед DoFinal в обеих ветках (шифрование и расшифровка). На том же телефоне после исправления получены
PASS enable и PASS decrypt с реальным отпечатком. Проверка интерфейсных сценариев первого предложения и настроек
остаётся в MobileChecks; это отдельная проверка от аппаратного round trip.
После установки 0.8.2 поверх рабочего кошелька пользователь также подтвердил успешное включение биометрии
и повторный вход после блокировки. Для проверки не потребовались удаление приложения или сброс кошелька.

`tools/test-android-signing.ps1` на подключённом Android устанавливает два пустых QA APK отдельного пакета
network.minter.wallet.signingcheck: старый сертификат → новый с lineage. Проверяет сохранность контрольного файла
через PackageManager и удаляет только созданный QA-пакет. Рабочий кошелёк не читает и не меняет.
На подключённом Android API 36 переход и сохранение данных подтверждены. Проверка подписи не проверяет биометрию;
аппаратная проверка с реальным отпечатком описана отдельно выше.
